# Aplicativos JavaScript e Electron distribuídos

Adaptação de [REA v36 — javascript-applications](https://github.com/morluto/rea/blob/6d8f95e38dfc847d911430483b812ff4951b373d/.agents/skills/reverse-engineer-anything/references/javascript-applications.md), MIT. Siga [gate da skill local](../SKILL.md) para instalações, execução e capturas.

1. `analyze_javascript_application` recebe **ASAR ou árvore extraída do usuário** diretamente, sem `open_binary` nem provedor nativo. Comece por findings, cobertura, desconhecidos e grafo; source maps também são análise **estática**. Para resposta grande, use `detail: "summary"` e `inspect_analysis_view` com `parent_evidence_id`; se `resource_constraint` de transporte, use o `evidence_reference` informado para resumo ou página de módulos. `export_evidence_bundle` escreve arquivo somente no caminho aprovado. Não repita produtor só para ver menos campos.
2. Investigue preferências BrowserWindow, preload/contextBridge, IPC, processos utility e módulos nativos como sintaxe observada. Somente canal IPC literal e único permite inferir pareamento; canal dinâmico fica em aberto. `.node` solicitado não comprova export nativo nem alcançabilidade/runtime.
3. Depois de obter seed literal (módulo, rota, string, IPC, API, export), `trace_application_feature` investiga uma hipótese/direção. Use Evidence da aplicação, referenciado por ID **somente** quando servidor anunciar retenção; caso contrário envie Evidence completo inline. Evidence nativa combinada exige digest **exatamente** igual ao artefato associado.
4. Versões: analise cada versão uma vez e use `compare_application_versions`; aceite somente correspondências por digest, source map, fingerprint estrutural ou semântica não baseada em ordinal. Nome minificado/ordinal não é identidade estável; ausência/remoção exige cobertura completa do lado oposto. Para diferença de **forma de retorno** de export, `compare_javascript_export_shapes` recebe paths/exports explícitos e Evidence dos dois lados. Leia `property_inventories`, `presence`, source ranges, JSON Pointer e variantes: nomes observados podem ter valores desconhecidos; buracos de array não são propriedades observadas. Não converta `unknown` em `removed`.
5. Quando a pergunta exige comportamento real, solicite aprovação para rodar/capturar versões reais no escopo do usuário e cruze com [runtime-observation.md](runtime-observation.md). Uma chamada estática jamais prova que um módulo foi executado.

Referências retidas aceitam `{"kind":"retained-evidence","evidence_id":"<ID retornado nesta conexão>"}` onde anunciado; versões anteriores a 4.1.0 podem exigir Evidence completo. `close_binary` limpa referências da sessão; exporte bundle antes de fechar se precisar de persistência.
