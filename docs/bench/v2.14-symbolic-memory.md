## Caveats

- **The 95% is an upper bound, not the expected real-world number.** This fixture is favorable to compression — bodies are pure tool output (grep dumps, glob trees, file contents) where the summary captures all reasoning value in 5-10 words. Real swarm/auto sessions mix that with edits, multi-turn agent dialogues, and rich subagent reports where the summary needs to retain more. Expect real-world compression in the **40-70%** band — closer to Tencent's published −33% (SWE-bench) and −61% (WideSearch) than this number.
- **Synthetic bodies** — Tencent measured on real benchmarks. This bench is a unit test for the mechanism, not a workload prediction. The honest claim is "the pipeline works and is lossless," not "you will save 95% on your code."
- **Token estimation is approximation** (bytes÷4). Actual BPE tokenization differs by 5-15% depending on content. Order-of-magnitude only.
- **No cache simulation** — Anthropic prompt cache could push real savings higher (canvas is stable across turns; raw tool history is not). This bench measures naive in-context size.
- **No agent reasoning overhead** — the agent still reads the canvas. Net win requires ≥1 turn benefiting from the compressed view; sessions <30 calls should not activate this (overhead > savings).
