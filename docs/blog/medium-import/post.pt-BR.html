Dev Team Kit — 39 Especialistas Dentro do Seu Agente de IA. E Medimos Tudo.

TL;DR: Um plugin Apache-2.0 que transforma Claude Code, Cursor, Windsurf e qualquer agente compatível com MCP num time completo de desenvolvimento virtual: 39 skills especialistas (PO, designer, backend, frontend, QA, security, SRE, …), 15 subagents despacháveis, 32 slash commands, 7 pipelines YAML executáveis, modos autônomos, memória persistente entre sessões, e economia de tokens embutida. Rodamos um benchmark público em cada peça. 92.6% de pass rate. +1.84 delta médio de qualidade. 53/53 testes E2E verdes. Tudo em github.com/felvieira/claude-skills-fv.

O que tem no kit

O Dev Team Kit instala como plugin do Claude Code (ou via shell script em qualquer agente compatível com MCP) e imediatamente dá ao modelo um time estruturado pra despachar trabalho. As peças:

39 skills especialistas (por categoria)

  • Gestão e Coordenação (16): Context Manager, Orchestrator, Documenter, Reviewer, Repo Auditor, Asset Librarian, Observability/SRE, Data Analytics, Accessibility, Migration & Refactor, Release Manager, AI Integration Architect, Prompt Engineer, Video Integration, CLAUDE.md Generator, Cost Tracker, Session Summary, Smart Suggestions, Detective Spec, Skill Author, Architecture Deepener.
  • Produto e Design (4): PO, UI/UX Designer, Design Intelligence, Web Asset Generator.
  • Desenvolvimento (4): Backend Engineer, Frontend Engineer, Motion Designer, Mobile/Tauri.
  • Conteúdo e Discovery (2): Marketing Copy, SEO Specialist.
  • Qualidade e Entrega (5): QA Engineer, Security Reviewer, Static Analysis, TDD Engineer, Deploy Engineer.

Cada skill é um playbook markdown com tabelas anti-racionalização, handoff chains apontando pra próxima skill, paths persistentes de artefato, e evidence anchors. Catálogo completo: README → The 39 Specialists.

15 subagents despacháveis

Pra quando você quer um turno isolado com contexto fresh: code-reviewer, security-auditor, test-engineer, orchestrator, debugger, 4 Detective subagents pra engenharia reversa de legado, 5 subagents de Static Analysis (semgrep-scanner, semgrep-triager, codeql-runner, sarif-parsing, variant-analysis), e o auditor anti-AI-writing.

Os modos autônomos

O kit traz 3 níveis de autonomia dependendo de quão hands-off você quer ser:

  • /auto — Agente único roda sua task end-to-end, para quando os testes passam. Bom pra task pequena.
  • /loop — Loop multi-agente com polishing pass. Suporta --parallel N com worktrees git isolados, --polish=none|light|standard|full, backoff classificado, token cap, condições stop-when, e 9 exit codes pra integração CI. Configurável: agente claude ou codex.
  • /swarm — Autonomia total. Prompt único → PR mergeable. Worktree isolado + Ralph loop (contexto fresh por story) + 4 agentes de review paralelos + self-fix CRITICAL/HIGH + PR automático no GitHub. Protocolo.

Mais um intent classifier baseado em hook que detecta a intenção do seu prompt (feature / bug / refactor / spike / etc.) e auto-sugere o command certo. 4 níveis configuráveis: Manual / Passivo / Ativo (padrão) / Autônomo (só CI). Policy de auto-orchestration.

Como economiza seus tokens

Conta de token é real. O kit luta em 5 frentes:

  • Compressão de output — strip ANSI, dedup de linhas adjacentes, colapsa listings de diretório, filtro hint-aware (git log / npm install / output de teste), truncação head-tail. 13% de redução single-call medido em bench público com 5 fixtures.
  • Cross-call MinHash dedup (v2.9.0) — janela deslizante de 16 chamadas com FNV-1a exato + bottom-k MinHash + Jaccard ≥0.85 fuzzy. Detecta re-runs do mesmo comando em loops autônomos. 98% de redução em second-run medido.
  • Model routing — Haiku pra boilerplate, Sonnet pra implementação, Opus só pra arquitetura. Enforced via hook.
  • Progressive skill loading — skills carregam só quando keyword de trigger dispara (sem pré-carregar). ~31k tokens economizados por sessão que seriam gastos com skills inativas.
  • Pipeline mínimo suficiente do Orchestrator — pra qualquer task, corta skills irrelevantes com justificativa explícita. Exemplo: feature de export CSV cortou 8 skills (UI/UX, Frontend, SEO, Deploy, etc.) ≈ 24k tokens.

Mensurável via /savings — command embutido que reporta por sessão: tokens economizados, USD prevenido, riscos bloqueados, hot files. Heurísticas declaradas em policy.

Como mantém correto

O mecanismo do kit não é "saber mais." É enforçar estrutura que o modelo frio não produz espontaneamente:

  • Paths persistentes de artefato — skills nomeiam onde escrever (docs/repo-audit/current.md, _detective_sdd/, …).
  • Handoff chains — todo output aponta pra próxima skill por número (→ skill 06 → skill 11).
  • Tabelas anti-racionalização — toda skill crítica tem tabela "racionalização vs realidade" pra pegar bias mid-execução.
  • Evidence anchors — skills detective exigem [evidence: file:linha] + tier de confiança.
  • Suppression gates — semgrep-triager bloqueia // nosemgrep sem aprovação explícita.
  • Memória entre sessões — learned-skills/ por projeto com score 0-1, decay semanal, auto-archive abaixo de 0.3. policy.

19 hooks de ciclo de vida rodam automaticamente: pre-execution gate, keyword detector, context guard, model routing, post-tool verifier, intent classifier, persistent mode, simplify-ignore protection. Tabela de hooks.

O que testamos

Dois tipos de teste:

  1. Bench de isolamento — 53 cenários. Mesmo prompt, mesmo modelo (claude-sonnet-4-6), com vs sem o kit. Rubrica: 5 critérios × 1-5. Pass = delta ≥ 1.5.
  2. End-to-end — 3 testes reais. App do zero (33/33 testes Jest), pipeline completo com handoffs (12/12 + Security pegou o que QA perdeu), feature em repo existente (8/8, zero dependência inventada).

Quando o bench falha, corrigimos

Primeira rodada teve 4 problemas. Três eram gaps de skill, um era cenário fácil demais. Corrigimos os 4 e rodamos de novo:

  • Skill 25 (AI Integration Architect) — era +1.0 FAIL. Templates eram stubs de 3-9 linhas. Escrevemos 422 + 225 linhas reais. → +2.0 PASS.
  • Skill 07 (Deploy Docker) — era +1.3 MARGINAL. Rollback usava prev-tag hardcoded, bloco SSL assumia certbot já rodado. Adicionamos persistência .last-tag + ssl-init.sh idempotente. → +1.8 PASS.
  • Code-reviewer agent — era +1.0 FAIL. Cenário de teste fácil demais. Reescrevemos com PR de 23 arquivos e 8 bugs sutis. → +2.29 PASS.
  • Skill 24 (Release Manager) — continuou near-miss (+1.2). Não é problema da skill: cenário com teto de baseline forte.

O princípio que isso estabelece: cada FAIL no bench vira fix concreto na versão seguinte. Não justificamos achados. Corrigimos e medimos de novo.

O que deliberadamente não testamos

Honestidade importa mais que parecer completo. Lista do que pulamos:

  • Geração de imagem contra API real do fal.ai (queimaria créditos sem mudar conclusão)
  • Multi-plataforma — só validado em Claude Code. Cursor/Windsurf/Gemini CLI listados como suportados mas não testados nessa rodada.
  • /swarm com PR real aberto no GitHub (working tree estava ocupada durante o bench)
  • /loop --parallel com worktrees reais (subprocess, consome tempo)

Estão na seção "Honestidade" do relatório público. O kit não está pronto — mas medimos o que entregamos.
