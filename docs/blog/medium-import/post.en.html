TL;DR: An Apache-2.0 plugin that turns Claude Code, Cursor, Windsurf and any MCP-compatible agent into a full virtual dev team: 39 specialist skills (PO, designer, backend, frontend, QA, security, SRE, …), 15 dispatchable subagents, 32 slash commands, 7 executable YAML pipelines, autonomous modes, memory across sessions, and built-in token savings. What's in the kit

The Dev Team Kit installs as a Claude Code plugin (or via shell script on any MCP-compatible agent) and immediately gives the model a structured team to dispatch work through. The pieces:

  • Product & Design (4): PO, UI/UX Designer, Design Intelligence, Web Asset Generator.
  • Development (4): Backend Engineer, Frontend Engineer, Motion Designer, Mobile/Tauri.
  • Content & Discovery (2): Marketing Copy, SEO Specialist.
  • Quality & Delivery (5): QA Engineer, Security Reviewer, Static Analysis, TDD Engineer, Deploy Engineer.

Each skill is a markdown playbook with anti-rationalization tables, handoff chains pointing to the next skill, persistent artifact paths, and evidence anchors. Full catalog: README → The 39 Specialists.

The autonomous modes

The kit ships three levels of autonomy depending on how hands-off you want to be:

  • /auto — Single agent runs your task end-to-end, stops when tests pass. Good for small tasks.
  • /loop — Multi-agent loop with polishing pass. Supports --parallel N with isolated git worktrees, --polish=none|light|standard|full, classified backoff, token cap, stop-when conditions, and 9 exit codes for CI integration. Configurable: claude or codex agent.
  • /swarm — Total autonomy. Single prompt → mergeable PR. Worktree isolation + Ralph loop (fresh context per story) + 4 parallel review agents + self-fix CRITICAL/HIGH + auto PR on GitHub. Protocol.

Plus a hook-based intent classifier that detects your prompt's intent (feature / bug / refactor / spike / etc.) and auto-suggests the right command. Four configurable levels: Manual / Passive / Active (default) / Autonomous (CI only). Auto-orchestration policy.

How it saves your tokens

Token bills are real. The kit fights them on five fronts:

  • Output compression — strip ANSI, dedup adjacent lines, collapse directory listings, hint-aware filtering (git log / npm install / test output), head-tail truncation. 13% reduction single-call measured on a public 5-fixture bench.
  • Cross-call MinHash dedup (v2.9.0) — 16-call sliding window with FNV-1a exact + bottom-k MinHash + Jaccard ≥0.85 fuzzy. Detects re-runs of the same command in autonomous loops. 98% reduction on second-run measured.
  • Model routing — Haiku for boilerplate, Sonnet for implementation, Opus only for architecture. Enforced via hook.
  • Progressive skill loading — skills load only when a trigger keyword fires (not pre-loaded). ~31k tokens saved per session that would otherwise be wasted on inactive skills.
  • Orchestrator minimum-sufficient pipeline — for any task, cuts irrelevant skills with explicit justification. Example: a CSV export feature cut 8 skills (UI/UX, Frontend, SEO, Deploy, etc.) ≈ 24k tokens.

Measurable via /savings — built-in command that reports per-session: tokens saved, USD prevented, risks blocked, hot files. Heuristics declared in policy.

How it stays correct

The kit's mechanism isn't "knowing more." It's enforcing structure the cold model doesn't produce spontaneously:

  • Persistent artifact paths — skills name where to write (docs/repo-audit/current.md, _detective_sdd/, …).
  • Handoff chains — every output points to the next skill by number (→ skill 06 → skill 11).
  • Anti-rationalization tables — every critical skill has a "rationalization vs reality" table to catch bias mid-execution.
  • Evidence anchors — detective skills require [evidence: file:line] + confidence tier.
  • Suppression gates — semgrep-triager blocks // nosemgrep without explicit approval.
  • Memory across sessions — learned-skills/ per project with score 0-1, weekly decay, auto-archive below 0.3. policy.

19 lifecycle hooks run automatically: pre-execution gate, keyword detector, context guard, model routing, post-tool verifier, intent classifier, persistent mode, simplify-ignore protection. Hook table.

What we tested

Two test types:

  1. Isolation bench — 53 scenarios. Same prompt, same model (claude-sonnet-4-6), with vs without the kit. Rubric: 5 criteria × 1-5. Pass = delta ≥ 1.5.
  2. End-to-end — 3 real tests. App from scratch (33/33 Jest tests), full pipeline with handoffs (12/12 + Security caught what QA missed), feature in existing repo (8/8, zero invented dependencies).

When the bench fails, we fix it

First run had 4 problems. Three were skill gaps, one was a too-easy test scenario. We fixed all four and re-ran:

  • Skill 25 (AI Integration Architect) — was +1.0 FAIL. Templates were 3-9 line stubs. Wrote 422 + 225 real lines. → +2.0 PASS.
  • Skill 07 (Deploy Docker) — was +1.3 MARGINAL. Rollback used hardcoded prev-tag, SSL block assumed certbot already ran. Added .last-tag persistence + idempotent ssl-init.sh. → +1.8 PASS.
  • Code-reviewer agent — was +1.0 FAIL. Test scenario was too easy. Rewrote with 23-file PR and 8 subtle bugs. → +2.29 PASS.
  • Skill 24 (Release Manager) — stayed near-miss (+1.2). Not a skill issue: scenario has a strong baseline ceiling.

The principle this establishes: every FAIL in the bench becomes a concrete fix in the next version. We don't rationalize findings. We fix them and measure again.

What we deliberately did not test

Honesty matters more than looking complete. Skip list:

  • Image generation against real fal.ai API (would burn credits without changing conclusion)
  • Multi-platform — only validated on Claude Code. Cursor/Windsurf/Gemini CLI listed as supported but not bench-tested this round.
  • /swarm with a real PR opened to GitHub (working tree was busy during the bench)
  • /loop --parallel with real worktrees (subprocess, time-consuming)

These are in the public report's "Honesty" section. The kit's not done — but we measure what we ship.
