# Plano completo v2.19.0 — Absorção dos 10 itens

- **42 skills** numeradas (`skills/NN-name/SKILL.md`)

5. **Updates de docs em batch** — MEMORY.md, CHANGELOG.md, WIKI.md, SKILLS-OVERVIEW.md atualizados juntos no final

## 1.3 Skill `44-handoff-context` — Transferência entre sessões/agentes

**Fonte:** [mattpocock/skills/productivity/handoff](https://github.com/mattpocock/skills/tree/main/skills/productivity/handoff) (MIT)

**O que é:** prepara contexto enxuto pra outra sessão (Claude diferente, dev humano, ou outro agente) pegar de onde parou.

**Por que cabe no kit:**
- Skill 31 (session-summary) já existe — faz **resumo retrospectivo**
- Skill 08 (context-manager) faz **gestão dentro da sessão**
- Falta: **handoff prospectivo** ("aqui está o pacote pra você continuar") — diferente de resumo

**Diferenças vs skill 31:**

| | Skill 31 (session-summary) | Skill 44 (handoff-context) — NOVO |
|---|---|---|
| Foco | Retrospectivo (o que aconteceu) | Prospectivo (o que falta + como continuar) |
| Audiência | Próxima sessão **minha** (mesmo modelo) | Outro agente/dev (cego, sem contexto) |
| Formato | Log markdown com decisões | Pacote acionável: setup commands + estado + próximo passo |
| Trigger | Fim de sessão | "passar bastão", "outro dev vai pegar", "delega" |

**Como integra:**
```
skills/44-handoff-context/SKILL.md  ← novo
  triggers: "handoff", "passar bastão", "delega pra outro", "transfer context"
  output template: 
    - Setup (git checkout, branch, deps)
    - Estado atual (o que tá implementado, o que tá quebrado)
    - Próximo passo (1 ação específica, não roadmap)
    - Armadilhas conhecidas
  
  consome: skill 31 (session-summary) se existir log do dia
  consome: docs/repo-audit/current.md (estado real do repo)
  produz: docs/handoffs/YYYY-MM-DD-<feature>.md
```

**Arquivo:** ~70 linhas

## 1.4 Skill `45-post-deploy-canary-monitor` — Vigília pós-deploy

**Fonte:** [gstack/canary](https://github.com/garrytan/gstack/tree/main/canary) (MIT)

**⚠️ Decisão importante:** já existe `skills/43-canary-deployment/` — esse é **release-canary** (traffic gradual durante deploy). O do gstack é **app-monitoring canary** (vigia produção pós-deploy: console errors, screenshots vs baseline, regressões de perf). **Skills diferentes, escopos diferentes.**

**Por que cabe no kit:**
- Skill 43 (canary-deployment) cobre **promoção controlada** (deploy → 1% → 5% → 50% → 100%)
- Skill 07 (deploy-docker) cobre **packaging e push**
- Skill 20 (observability-sre) cobre **definir** alerts/SLOs
- **Gap real:** depois do deploy fechar, **quem fica vigiando** as primeiras horas/dias procurando regressão silenciosa?

**Como integra:**
```
skills/45-post-deploy-canary-monitor/SKILL.md  ← novo
  triggers: "monitor deploy", "watch production", "verify deploy stuck",
            "post-deploy check", "regressao silenciosa"
  inputs:
    - URL produção
    - Baseline pre-deploy (screenshots + métricas)
    - Threshold de abort
  flow:
    1. Coleta baseline (skill 20 → métricas, anthropic-skills:webapp-testing → screenshots)
    2. Loop de polling (configurable: 5min / 15min / 1h)
    3. Compara com baseline (console errors > 0, LCP regressão > 20%, screenshot diff)
    4. Alerta → escala pra skill 43 (rollback automático)
  output: docs/canary-runs/YYYY-MM-DD-<release>.md (timeline + decisão)
```

**Dependências:**
- `anthropic-skills:webapp-testing` (já disponível como Skill) para Playwright screenshots
- skill 20 (observability-sre) para métricas
- skill 43 (canary-deployment) como **escalação** se detectar regressão

**Arquivo:** ~120 linhas (mais elaborado — workflow real)

## 2.1 `commands/instinct-export.md` + `instinct-import.md` + `instinct-promote.md`

**Por que cabe no kit:**
- Já temos `.bot/learned-skills/` (per project, score 0-1, decay semanal, auto-archive <0.3)

**Como integra:**
```
commands/instinct-export.md     ← novo
commands/instinct-import.md     ← novo  
commands/instinct-promote.md    ← novo
scripts/instinct.mjs            ← novo (~120 linhas, zero-dep, lê/escreve .bot/learned-skills)

  → consome: .bot/learned-skills/*.md (formato existente)
  → produz: instincts-bundle.json (formato compatível com agentskills.io?)
```

## 2.2 `commands/multi-plan.md` — Disagreement gate Claude+Codex

**Fonte:** [ECC](https://github.com/affaan-m/ECC) — `/multi-plan` (MIT)

**O que faz:** roda plan **paralelo** em 2+ modelos (Claude + Codex), compara outputs, surface só **discordâncias** ao user pra decidir.

**Por que cabe no kit:**
- Skill 40 (parallel-dispatcher) já paraleliza, mas é **fan-out** (mesmo modelo, slices diferentes)
- Subagent `codex:rescue` já existe pra delegar follow-up
- Falta: **scatter-gather de modelos discordando no MESMO plano**

**Como integra:**
```
commands/multi-plan.md         ← novo (~50 linhas)
  flow:
    1. Recebe contexto da feature
    2. Spawn paralelo: claude (sonnet/opus) + codex (gpt-5)
    3. Cada um produz plano independente
    4. Diff dos planos → identifica:
       - Convergências (alta confiança, aprovar)
       - Divergências (decisão humana necessária)
    5. AskUserQuestion só nas divergências
    6. Plano final = união aprovada
  uses: 
    - skill 40 (parallel-dispatcher)
    - codex:rescue agent
    - policies/trade-off-resolution.md
```

**Arquivo:** 1 command (~60 linhas) — sem novo script (reusa infra existente)

## 2.3 `commands/aside.md` — Side question sem perder contexto

**Fonte:** [ECC](https://github.com/affaan-m/ECC) — `/aside` (MIT)

**O que faz:** responde pergunta side **sem contaminar** task principal (não puxa contexto da task, não polui resposta com refs à task).

**Por que cabe no kit:**
- Skill 08 (context-manager) gerencia contexto
- Falta: **interrupção declarada** que não contamina nem é contaminada

**Como integra:**
```
commands/aside.md   ← novo (~40 linhas)
  uso: /aside como funciona X? (Y é tangencial à minha task atual)
  efeito:
    - Resposta da pergunta isolada
    - Não atualiza task atual
    - Não puxa contexto da task atual no scope da resposta
    - Não atualiza memória persistente
```

**Arquivo:** 1 command (~40 linhas)

## 2.4 `commands/skill-health.md` — Dashboard de saúde do portfolio

**Fonte:** [ECC](https://github.com/affaan-m/ECC) — `/skill-health` (MIT)

**O que faz:** mostra dashboard de **saúde do portfolio de skills**: quais nunca foram invocadas, quais têm description fraca, quais têm overlap, quais estão stale.

**Por que cabe no kit:**
- Skill 35 (skill-author) cria/edita skills
- `evals/triggers/` já mede triggering accuracy
- Falta: **visão agregada do portfolio** (não eval individual)

**Como integra:**
```
commands/skill-health.md       ← novo (~30 linhas)
scripts/skill-health.mjs       ← novo (~150 linhas, zero-dep)
  lê:
    - skills/*/SKILL.md (frontmatter description)
    - evals/triggers/*.jsonl (acertos/erros de triggering)
    - hooks/scripts/skill-invocation-log.* (uso real, se houver)
  produz:
    - Tabela markdown: skill | trigger accuracy | last used | description quality | overlap with
    - Highlights: stale (>30d sem uso), weak description (<50 chars), overlap (>3 triggers comuns)
  output: docs/skill-health.md (regenerado a cada execução)
```

**Arquivo:** 1 command (~30 linhas) + 1 script (~150 linhas)
